# 0.22.0 存錢目標與完整備份契約

> 日餘拆分註記（2026-10-14）：本文保留原專案的歷史版本、日期、驗證結果及限制，不代表日餘本輪重測。現行程式磁碟目錄為 `web/`；HTTP仍為 `/local-first/`。Windows請雙擊根目錄 `start_local_first.local.cmd`，歷史 Python／Node 指令不是目前使用者操作入口。

**僅供合成資料測試，請勿輸入真實帳目。IndexedDB 未加密，Python Web 尚未被取代。**

## 使用與計算

「規劃 → 目標」預設收合，記帳首頁不要求先設定。目標名稱、正數目標金額、非負已存總額、期限或不限時可更改；完成由使用者自行確認。進度最多100%，文字保留真實超額；期限提示只在查看時顯示，可關閉，不產生推播或自動完成。

每月分配以 `goal_id` 明確連結目標，同名不自動連動。儲存前後按「目標 ID＋月份」加總貢獻：`差額＝新貢獻－上次貢獻`，`新已存＝目前已存＋差額`。重複儲存差額為零，不重複計入；移除連結或項目減去原貢獻，不改其他月份。收入新增／更改不自動改分配。

手動校正直接把當下已存設為輸入值，保存前值、後值及差額；不抹掉以前的分配貢獻。例如原分配1000元、手動設為300元，再移除原分配會使結果為−700元；依已確認規則整筆拒絕、保留輸入，須先自行校正。不得自動歸零或丟掉差額。

已完成目標不能新連結或增加貢獻；既有連結可保留、減少或移除，但仍不得使已存低於0。要增加先自行更改完成狀態。這些都是規劃紀錄，不新增消費、收入、轉帳或實際存款，也不扣預算。

## 儲存與相容

IndexedDB v8 新增兩個 store，共22個含 meta。舊 v2～v7 在原升級交易新增缺少的 store、驗證原資料；升級不重寫原資料列與容量 metadata。資料庫名稱及固定127.0.0.1:8768不變。失敗中止整個交易，不清除原帳本。

有目標資料、調整紀錄或分配目標連結時輸出 JSON v7，共二十一類；沒有新資料仍依既有資料選原格式。JSON v1～v6仍可驗證及還原至完全空白帳本，新欄位不自動補連結。舊 Python／舊 local-first 不支援v7，必須安全拒絕，不能刪欄位或改版本降級。加密封裝v1、密碼流程、每次隨機參數及完整性驗證不變；IndexedDB本身仍未加密。

| 資料 | 欄位與驗證 |
|---|---|
| `goals` | `id,name,target_cents,saved_cents,deadline,remind,completed,revision`；名稱1～200字、不含控制字元；目標正數、已存非負；期限為有效ISO日期或null；開關0／1、revision為有效整數。 |
| `goal_actions` | `id,goal_id,kind,month,before_cents,after_cents,delta_cents,contribution_before_cents,contribution_after_cents`；順序即操作順序，引用必須存在。 |
| 分配項目 | 原`id,name,cents`保留，僅明確選擇才新增`goal_id`；舊分配沒有此欄位。 |

金額用十進位整數cents字串，計算用BigInt。新輸入沿用十億元台幣／最多兩位小數的既有上限，已存允許0，目標不允許0。累積或匯入的較大合法金額可在編輯其他欄位時原值保留；新校正值仍受一般輸入上限限制。保存總額、貢獻、revision及匯入整數受signed64上限約束；完整備份仍限64MiB／100000列。

`manual`紀錄的month及貢獻欄位為null；`allocation`紀錄有有效月份與前後貢獻，差額須相等且非零。每個目標紀錄從0開始連續，前值須接上一次後值，最終後值須等於已存總額；每個目標／月份貢獻同樣連續，最終須等於目前保存分配的加總。重複ID、錯誤引用、畸形金額、順序或差額不一致全部拒絕。

## 交易與升級操作

同一分配提交，在既有單一IndexedDB寫入交易重新讀取分配與每個受影響目標，驗證選取時revision、完成狀態、差額及容量，再一起更新分配、目標、紀錄與meta。任一衝突、配額或中止全部回滾；失敗保留表單，不誤報成功。純查看不寫入。

快取為`local-first-offline-0.22.0-v1`，仍18個本機必要資源。先保留草稿及完整備份、保持服務到資源下載完成，關閉同來源全部舊頁再重開；不強制刷新、不skipWaiting、不清除帳本。升級後不要以舊程式開啟已升級的資料庫。
