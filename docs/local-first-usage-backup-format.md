# 使用期間與完整備份 JSON v4

0.16.0，2026-10-05。**僅供合成資料測試，請勿輸入真實帳目；IndexedDB 未加密，Python Web 尚未被取代。**

## 資料流

原消費表單的選用使用期間 → 驗證原消費與附屬欄位 → 同一寫入交易保存一筆消費、既有操作紀錄、追蹤列及容量 metadata → 交易完成才顯示成功。提醒只讀取帳本，依台灣今天推算，沒有背景排程、自動記帳、實際庫存或額外費用。

- 使用起始日算第 1 天，預計用完日為起始日＋天數－1。有效 ISO 日期；天數為整數 1～36500，計算後日期不得超出 9999 年；提前提醒天數為整數 0～36500，預設 7。未開始或超過提醒門檻不顯示。
- 沒填天數的新消費不建立追蹤。首次保存前，未手選的起始日跟隨消費日；保存後更改消費日不移動追蹤起始日。自動來源原入帳日期仍不可更改。
- 清空既有天數或按停止按鈕，再儲存才生效。停止保留原追蹤列、原消費與歷史；再次更改可重新填寫天數及開啟提醒。關閉提醒不等於停止追蹤。消費撤銷後不提醒，也不刪除追蹤。
- 每日平均成本預設不顯示。以原精確 cents 除以天數，BigInt 四捨五入至四位小數元／天，標示約數；小於可顯示精度的正值顯示 `<0.0001`。不修改原金額，不產生每日消費。所有支出統計沿用原消費。
- 共用收合的「快結束」位置：消耗品顯示剩餘天數／今天預計用完／預計已用完；分期沿既有進度，只有啟用、未完成且剩 1 期才顯示。已撤銷的已入帳期仍計為已處理，不重建。不符合時隱藏整區。

## IndexedDB v5／JSON v4

名稱及固定 `127.0.0.1:8768/local-first/` 不變。v5 在原十五類資料之外新增 `usage_periods`，含 meta 共 17 個 store。v2／v3／v4 升級先在版本交易內檢查原結構、完整資料與 metadata；新空 store 不改原備份 bytes。損壞或任一步失敗都完整中止，保留原結構；原 v1 遷移仍支援。

JSON `format` 仍為 `life-ledger-backup`。v4 完整包含原十五類與下列一類，所有欄位必填，額外欄位拒絕：

| 欄位 | 契約 |
| --- | --- |
| expense_id | 引用已存在生活消費 ID，可已撤銷；每筆消費最多一列，store key 就是此 ID |
| started_on | 有效 ISO 日期，與消費日期獨立 |
| days | 整數 1～36500，預計結束日必須有效 |
| remind | 數值 0／1 |
| reminder_days | 整數 0～36500 |
| show_daily_cost | 數值 0／1 |
| active | 數值 0／1；停止為 0，保留其他欄位 |
| revision | 非負 signed 64-bit 整數，實際追蹤變更才遞增 |

所有追蹤更改都經既有消費編輯入口，同時增加 expense revision 並保存既有 before 消費快照；沒有另一套直接覆寫或追蹤 undo。相同資料不另增 tracking revision，但消費操作紀錄仍依既有更改語意保存。兩頁同時使用舊 expense revision，只有一頁能成功；另一頁保留草稿並要求重新載入。初次新增保留提交 ID，失敗重試不能重複新增同筆。

共用 `backup.mjs` 驗證金額、日期、引用、重複列及完整形狀；總列數最多 100000（不含 settings），JSON 明文最多 64 MiB，JSON 深度上限 12。追蹤與其他所有資料都計入容量。寫入中斷、容量不足、request 成功後 abort 不留半筆消費或追蹤。

## 相容、更新與復原

有追蹤列時完整匯出 v4／十六類，即使全部停止或關聯消費撤銷也不可省略。沒有追蹤列時依收入／年度資料選舊 v1／v2／v3。舊 v1～v3 可在全新空白帳本驗證後原子還原，補空追蹤 store。

`.llbk` 加密封裝 v1、PBKDF2-SHA-256 600000 次與 AES-256-GCM 不變；解密後仍交同一完整備份驗證，明文／加密檔容量不變。現有 Python 及舊 local-first 拒絕 JSON v4，不會靜默忽略追蹤資料；不能改版本或刪除新類別來降級。沒有新增 Python Web／Discord 功能或第三方依賴。

升級前先保存／自行保留草稿及完整備份；保持服務開啟至 17 個必要資源完整下載，關閉此來源所有舊頁後再開，不自動 skipWaiting 或清除資料。新結構不支援直接開回舊程式。

請用合成資料親自確認新 v4 加密下載檔存在，再在另一全新空白瀏覽器設定檔、同一固定網址還原，核對十六類、停止／撤銷歷史及提醒，再關頁重開與再次備份。原帳本開啟失敗時不要清除網站資料或覆蓋原帳本，先保留設定檔；沒有可用備份先停止與查明原因。密碼只保護備份檔，不能取回忘記的密碼，也不防禦本機惡意程式、擴充套件或已解鎖的電腦。
