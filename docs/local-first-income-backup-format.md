## 版本及相容性

- 外層仍為 `format: "life-ledger-backup"`、`version`、`data`，所有欄位皆嚴格驗證，不接受未知欄位或版本。
- JSON v1 原有九類資料及其欄位不變。收入、操作歷史、分配及建議偏好皆空時仍匯出 v1，保持 Python 搬移相容性；任何新增類別有資料（包含已作廢收入或零元分配）即匯出 v2，完整包含十三類資料，不裁切月份。
- 0.14.0 可讀 v1／v2；v1 還原時補四個空集合，不建立收入、分配或消費。完全空的 v2 再匯出可為 v1，沒有資料遺失。
- 現有 Python 及舊 local-first 不支援 v2，會安全拒絕，不能回存 Python。**不可手動改版本或刪除四類資料來假裝相容**；本輪不新增 Python 收入功能。
- `.llbk` 加密封裝仍是獨立 v1，參數、容量、隨機 salt／IV 及完整性驗證不變；解密後依內部 JSON 版本驗證。參閱[加密封裝契約](local-first-encrypted-backup-format.md)。加密備份不代表本機帳本已加密。

## 新增四類資料

原九類：`expenses`、`categories`、`payment_sources`、`budgets`、`recurring_rules`、`recurring_versions`、`shortcuts`、`actions`、`settings` 原樣保存。

| 類別 | 嚴格欄位／用途 |
| --- | --- |
| `incomes` | `id`、`received_on`、`cents`、`name`、`voided`、`revision`；手動已收到的收入，作廢保留資料 |
| `income_actions` | `id`、`income_id`、`before`、`undone`；新增為 null 快照，更改／作廢保存原收入完整快照；陣列順序就是操作順序，本輪不提供復原操作 |
| `monthly_allocations` | `month`、`items`、`excluded_recurring_ids`、`revision`；每月一列，項目為 `id`／`name`／`cents`，排除引用現有定期規則 |
| `allocation_preferences` | `recurring_id`、`excluded_from_month`、`revision`；每規則最多一列，從指定月份起排除建議，不更改原規則 |

收入／操作 ID 與原有帶 ID 的列共同不可重複，採既有 1～64 字小寫識別格式。快照必須與引用收入有相同 ID；分配月份及偏好規則鍵不可重複。每月最多 100 項，項目 ID 及名稱在同月不可重複；收入名稱最多 200 個 Unicode 字、分配名稱最多 30 字，禁止控制字元。日期／月份須為合法 ISO 日曆值；所有引用必須存在。

金額用十進位 cents 字串；收入為正數，分配可為零，最高保留 signed 64-bit 正值，以 BigInt 計算。新表單沿用十億元、最多兩位小數上限，不用顯示文字加總；收入表單不接受晚於操作當下台灣今天的日期。合法歷史備份的未來收入保留，但截至今天以前才計入實收。revision 使用既有精確整數及 signed 64-bit 上限，不能靜默覆寫舊畫面。

總列數（settings 不算一列）仍最多 100000，新四類一起計入；JSON UTF-8 最大 64 MiB，加密檔最大 67108927 bytes。沿用重複 JSON key、UTF-8、精確數字、深度、型別、形狀、容量及引用驗證；不接受新增分配項目以外的任意欄位。

## 儲存、升級及還原

IndexedDB 名稱與固定 8768 來源不變，結構由 v2 升為 v3：原九類與 meta 保留，增加上述四個 store。升級在原生版本交易內驗證既有列與容量 metadata；失敗 abort，不能留下半個結構或重寫歷史。v1 單列舊結構仍走原子搬移；新版本開啟時舊連線會關閉，請先保存／保留草稿並關閉舊頁。升級後不支援降回舊程式開啟 v3。

新寫入重用既有完整快照及寫入交易工具。驗證當前 revision 與容量後，同一交易更新資料、收入 before 快照及 metadata；只有 complete 後顯示成功，quota／request 成功後 abort 全部回滾。還原先解密／完整驗證，顯示九或十三類筆數，確認後交易內重查完全空白；已建立預設帳本也不是空白，不覆蓋既有來源。

## 規劃語意

只有預設草稿「生活開銷」，可自行更改名稱、移除或新增項目；零元／空項目清單也可保存。各月獨立，不自動複製上月。分配可超過收入，差額只是規劃差額，不是存款餘額；收入更改／作廢不重寫分配。

建議採三種既有定期規則及應付月份的有效版本，短月取月底、歷史空白扣款日為 1 日。本月尚未到扣款日也可列為規劃建議，**不代表已收到／已消費或銀行扣款**。已停用、已完成分期依現有入帳期數（含撤銷）判定，不復活；每規則每月最多一次。當月排除只存該月份，往後排除另存偏好；兩者都不修改消費、定期規則、扣款日或版本。明確套用建議只填草稿，仍須按保存，不覆蓋已儲存安排。

未知後續格式建立新版本並明確拒絕，不能把新增資料省略作降級。完整驗證及未驗證範圍見[本機驗證文件](local-first-browser-validation.md)。
