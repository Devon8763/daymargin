# 消費標籤與完整備份契約（0.18.0）

> 日餘拆分註記（2026-10-14）：本文保留原專案的歷史版本、日期、驗證結果及限制，不代表日餘本輪重測。現行程式磁碟目錄為 `web/`；HTTP仍為 `/local-first/`。Windows請雙擊根目錄 `start_local_first.local.cmd`，歷史 Python／Node 指令不是目前使用者操作入口。

**僅供合成資料測試，請勿輸入真實帳目。IndexedDB 未加密；Python Web 尚未被取代。**

標籤只關聯既有單筆生活消費，不改分類、來源、金額或定期規則。表單內新名稱是草稿，確認消費後才在同一交易保存消費、操作紀錄、標籤、關聯與容量 metadata；取消、驗證失敗或交易 abort 不留下空標籤。年度草稿確認也沿用同一消費寫入流程。捷徑及定期規則不攜帶標籤。

## 名稱與顯示

名稱移除前後空白及開頭的 `#`／`＃` 顯示符號，再作 NFC 正規化；限制 1～50 個 Unicode 字元，拒絕控制字元及無效代理字元。大小寫、內部文字與相容字形不自動合併，例如 `Travel`／`travel`、`Ａ`／`A` 是不同名稱。備份中的名稱必須已符合正規化，不在匯入時擅自合併。

隱藏只改 `hidden`，選單及字面輸入建議不顯示它，歷史分析與關聯保留；輸入完整名稱仍重用原 ID。移除須確認，刪除該定義及所有關聯（含已作廢消費），保留帳目、原金額、分類及既有 `actions.before`。受影響消費 revision 遞增，防止舊編輯草稿覆寫；標籤顯示狀態及關聯變更也遞增標籤 revision，舊移除確認不得漏掉新關聯。沒有新增標籤復原／undo 功能。

## IndexedDB 與 JSON

- 保留原來源及資料庫名稱，IndexedDB 原子升至 **v6**；新增 `tags`、`expense_tags`，共 19 個 store（含 meta）。舊 v2～v5 必須通過完整原資料及 metadata 驗證後才能升級；失敗保留原結構及資料，不清空帳本。
- 有標籤定義或關聯時，完整備份使用 **`life-ledger-backup` JSON v5／十八類**。原 v4 的十六類及欄位不變，另加下列兩類；隱藏、尚無關聯的定義也必須保存。沒有標籤資料仍依原資料選 v1～v4，不為顯示功能丟掉其他月份、年度、收入或使用期間。
- 舊 JSON v1～v4 可在空白帳本還原，新兩類初始化為空，不改原資料語意。舊 Python 及舊 local-first 不支援 JSON v5，必須拒絕；**不可刪去標籤欄位或改小版本號來降級**，否則會失去關聯與隱藏狀態。

| 類別 | 欄位／限制 |
| --- | --- |
| `tags` | `id`（既有 ID 規則且全帳本唯一）、`name`（正規化後唯一）、`hidden`（0／1）、`revision`（0～9223372036854775807 的精確整數） |
| `expense_tags` | `expense_id`、`tag_id`；複合鍵 `[expense_id, tag_id]` 唯一，兩端須引用實際存在資料，不能附帶額外欄位 |

仍限制完整明文備份 **64 MiB／100000 列／深度 12**，兩類及關聯計入總容量；金額、revision 使用原精確整數／lossless JSON 規則。畸形欄位、重複 ID／名稱／關聯或錯誤引用整筆拒絕，沒有部分還原。加密 `.llbk` **封裝 v1 不變**，解密後交給同一完整驗證；參數及檔案上限見[加密格式](local-first-encrypted-backup-format.md)。密碼只保護下載檔，不加密瀏覽器帳本，遺失密碼無法取回。

## 分析與升級

單一標籤分析預設全部時間，可加包含兩端的日期範圍；只統計截至台灣今天已入帳、有效、未作廢的四種來源生活消費，精確 cents 加總。隱藏標籤可查歷史。同一筆 1000 元有兩個標籤，分別查任一標籤均為 1000 元，不提供跨標籤加總。查詢與切區不寫入帳本、補記或建立標籤。

更新前先保存／自行保留草稿及完整備份，保持本機服務開啟至資源完整下載，關閉此來源全部舊頁後重新開啟。固定 `127.0.0.1:8768/local-first/`、CSP、17 個必要靜態資源及加密封裝不變；快取為 `local-first-offline-0.18.0-v1`，不自動 skipWaiting、刷新或清除帳本。實際合成驗收及需手測事項見[驗收紀錄](local-first-browser-validation.md)。
