# 日餘 UI／UX Skills 協作規範

本文件是 UI／UX 工作分工與授權入口，不是視覺方案。每輪先讀適用的 [AGENTS.md](../AGENTS.md)，保留未提交修改，再按問題選流程；Skill、資料集與官方預設流程均不授予額外修改權限。

2026-10-17使用者已核准全站第一版實作；唯一正式視覺／呈現基準為 [UI／UX第一版基準](ui-ux-design.md)，包含A、四區、D01～D04及五項UX整合。原候選與歷史驗證不取代本輪產品驗收。

## 產品方向與已確認偏好

品牌為「日餘」，Slogan 為「讓生活有度」。從輕鬆記錄日常收入與支出出發，幫助使用者理解生活、安排財務，需要時再使用完整管理功能。

- 先讓記帳快速、清楚、可靠，再提供規劃與分析；預設簡單、進階自由，首次開啟不要求大量設定。不以功能數量或誘導使用頻率為目標。
- Local-first、資料自主、隱私、復原能力與可靠性優先；帳號不是存取本機帳本的必要條件。未來線上功能須另外授權與規劃。
- 未來主要公開產品預計為手機 App；目前 Web 仍須適合桌面、鍵盤與窄螢幕。共用語意與原則不等於共用全部元件、導航或框架，不預建 App／shared 空殼。
- 第一眼能理解要做什麼，常用操作不藏在多層收合或進階選單。首頁只有記帳與搜尋不可移除；其他模組沿用使用者的顯示、排序、捷徑數量與收合偏好。
- 不因改版重設偏好、清除草稿、遺失搜尋條件或返回位置。四區維持「記帳／規劃／分析／設定」；改資訊架構須另提理由並取得同意。
- 減少重複說明、冗長提示與裝飾性資訊，一般教學集中說明頁；當下必要的錯誤、不可逆操作、資料保存與復原風險仍在操作處清楚呈現。
- 簡單不是只剩圖示；難理解時用短文字，所有控制保留可理解的無障礙名稱。文案用繁體中文，沿用「更改」「記錄消費」。
- 金額維持既有精度，整數不顯示 `.00`，有小數才顯示，保留千分位與「元」。圖表依問題選擇，不全套折線或一次堆滿，保留精確數字與可取得的明細。
- 收合與切換柔和、可中斷，不跳動、不阻塞輸入，尊重減少動態效果設定。
- 品牌名稱與 Slogan 已確認；第一版採A「柔和日常＋抽象太陽」，最終Logo造形仍未定，不自行擴大品牌設計。

以上是已確認方向與約束，不表示各項體驗均已實作或驗收。帳戶總覽、轉帳、同步等仍是未確認或待規劃構想，不可寫成現有功能。

## 分工與按問題選流程

這是專案分工，不是工具能力限制。一輪一個主要 Skill，交叉檢查限具體缺口，不強制兩套全跑、不無限迭代，也不要求兩個模型或子代理。

| 主要 Skill | 主要責任 | 使用約束 |
|---|---|---|
| UI UX Pro Max | 配色、繁體中文字體可讀性、字級、間距、圓角、視覺層級；最小必要 Design Tokens；按鈕、表單、卡片、導航、圖表的視覺與狀態；跨頁一致性與平台研究 | 既有規範優先，針對缺口做最小查詢。資料集只是候選，須驗證文字、字形與平台適用性；不因推薦新增 React、Tailwind、圖示套件、字型或 UI Framework，不機械套用財務 App、SaaS 行銷頁或原生手機模式，不為風格改流程、資訊架構或帳務語意。 |
| Impeccable | 任務流程、可發現性、資訊架構、認知負擔；記帳、搜尋、導覽、收合與返回；文案、層級、空狀態、錯誤、確認、回饋；無障礙、響應式、動態與完成後打磨 | 應用內以 Operate、說明內容以 Read 為主，不把記帳工具變成行銷展示頁。按目標選工作模式，不為使用 Skill 而全跑。 |

每輪開頭用一句話交代：**問題／範圍／主要 Skill／預期交付／不處理項目**，並標示「審查、方案或實作」。

| 問題 | 流程與停止點 |
|---|---|
| A. 操作難用、入口難找、文案太多 | Impeccable 主導，沿用視覺規範；只有缺口才查 UI UX Pro Max。審查交付有證據的問題與建議即停。 |
| B. 配色、字體、元件樣式、跨頁不一致 | UI UX Pro Max 主導；必要時由 Impeccable 檢查可讀性與操作影響。候選不自動定案。 |
| C. 新頁面或明確授權的大幅重新設計 | Impeccable 先釐清任務與資訊層級，再由 UI UX Pro Max 提供視覺候選；整合取捨供使用者選擇，不直接實作。 |
| D. 小型修正 | 只用必要 Skill 與既有規範，不重跑完整流程、不另建文件。 |
| E. 交付檢查 | 只查本輪受影響流程、視覺一致性、無障礙與安全狀態；不順便審查或重設全站。 |

## 已安裝模式與呼叫方式

2026-10-17 依本機原檔與[安裝紀錄](ui-ux-skills-installation.md)核對：Impeccable Skill **4.6.0**、Windows 引擎 **0.1.15**；UI UX Pro Max 為官方 CLI **2.15.0** 產生的主 Skill，`SKILL.md` 未另宣告獨立版號。未重裝或升級。原檔入口：[Impeccable](../.agents/skills/impeccable/SKILL.md)、[UI UX Pro Max](../.agents/skills/ui-ux-pro-max/SKILL.md)。

先在 Codex 開啟日餘專案。以下 `$…` 是給 Codex 的 Skill 提示，不是 PowerShell／CLI 子命令：

| 提示 | 用途及限制 |
|---|---|
| `$impeccable shape <範圍>` | 釐清任務、資訊層級與介面方案；交付 brief，確認後停止，不寫產品程式。 |
| `$impeccable critique <範圍>` | 使用體驗、可發現性與設計檢視。完整流程預設含獨立評估、瀏覽器／偵測證據及快照寫入，不等於完全唯讀。 |
| `$impeccable audit <範圍>` | 無障礙、響應式、效能等可驗證技術品質檢查；提出報告，不自動修正。 |
| `$impeccable distill <範圍>`／`$impeccable clarify <範圍>` | 減少複雜度／改善文案；可能修改介面，須明確區分只提方案與授權實作。 |
| `$impeccable adapt <範圍>`／`polish <範圍>`／`harden <範圍>` | 跨尺寸調整／細節打磨／錯誤與邊界狀態；實作仍須授權。`audit`、`adapt` 的 Web 與 native 參考文件不同，按實際平台選用。 |
| `$ui-ux-pro-max <問題與範圍>` | 研究視覺候選或核對既有規範；明示平台、只用本機資料、是否允許寫檔及是否僅候選。 |

必要操作說明：

- Impeccable 模式對照見 [routing](../.agents/skills/impeccable/reference/routing.md)、[shape](../.agents/skills/impeccable/reference/shape.md)、[critique](../.agents/skills/impeccable/reference/critique.md)、[audit](../.agents/skills/impeccable/reference/audit.md) 與 [Operate／Read](../.agents/skills/impeccable/reference/operate.md)。模式名稱不能一律當作可執行 CLI 動詞。Windows 引擎入口是既有 `.agents/skills/impeccable/scripts/impeccable.cmd`；例如 `context --target web/index.html` 是載入上下文，不是 `shape` 的 CLI 寫法。本輪只讀文件，未執行引擎。
- 唯讀時明示「不寫任何檔案、快照或設定，不注入／修改產品頁面」。這優先於 `critique` 快照、overlay 或其他預設副作用；省略步驟須列出，完整流程不符時標示受限／降級，不宣稱完整 critique。完整 critique 若依原版要求使用獨立子代理，須先確認本輪允許；一般協作不因此強制開子代理。
- UI UX Pro Max 的本機搜尋入口是 `.agents/skills/ui-ux-pro-max/scripts/search.py`。由代理使用既有 Python，帶 `-B` 避免快取寫入；單一問題用一個 `--domain`（如 `color`、`typography`、`chart`、`ux`），可加 `--max-results 3 --json`。查詢以 2～5 個關鍵詞聚焦一個意圖；結果不符最多縮窄重查一次，仍不符就明說無已驗證匹配。只有實際相符的已知技術棧才用 `--stack`，不把原生 JS／CSS 當成 Tailwind 專案。
- 只有授權整體視覺候選研究才用 `--design-system`；未加 `--persist` 不代表正式規範。`--persist`、`--output-dir`、`--page` 涉及持久化，`--force` 涉及覆寫，須有對應寫檔授權；核准前不執行。工具核對結果也不代替使用者核准。
- 不因 Skill 預設流程自動執行 `init`、`document`、`extract`、設計生成、素材下載、修復設定或介面修改；不修改官方 Skill 原檔以塞入日餘規則。不用的模式不執行。

若需要使用者開啟產品，雙擊根目錄 [start_local_first.local.cmd](../start_local_first.local.cmd)；不要求裸 `node` 指令。固定 8768 及使用者手測先依 AGENTS 確認舊服務已停止；不停止其他服務、不清除原帳本。一般規範工作不需啟動網站。

## 衝突、授權與安全邊界

財務正確性、資料安全、隱私、可靠復原，以及必要風險資訊和無障礙操作是不可交換的底線。符合底線後，依序考慮：

1. 已確認產品需求與本輪範圍。
2. 操作效率、可理解性與使用者控制。
3. 已核准設計規範。
4. 純美觀或裝飾偏好。

建議衝突時說明具體使用情境、取捨與推薦，不無條件累加；影響既有產品決定先詢問。**審查**只提出有證據的問題；**方案**只是候選；**實作**須有本輪明確介面範圍授權。核准候選不等於授權全站重設。

- 不擅改金額、日期、分類、收入分配、目標連動或帳務規則。規劃、預算、已記錄收支、草稿、預估費用與實際餘額分清楚；收入減支出不得稱為存款、資產或帳戶餘額。
- 不修改 IndexedDB、Migration、備份／加密格式、儲存識別或資料模型；保留 revision、交易、rollback、輸入驗證、XSS 防護與提交後失敗鎖定。交易已提交後的讀取／呈現失敗不可宣稱已回滾；維持寫入保護與重新載入確認。
- 不為簡化介面取消必要確認，不把儲存失敗顯示成成功。畫面只處理呈現與互動，核心維持規則與交易，不在 UI 複製帳務驗證。
- 不新增 CDN、追蹤、分析 SDK、外部字型、雲端處理、帳號需求或產品依賴。Impeccable 遙測維持關閉、Hook 維持未啟用；部分功能仍需連線，不自行呼叫外部目錄、素材或設計服務。
- 不把帳目、備份、秘密或個資放進查詢、log、截圖、bundle 或第三方服務；僅使用隔離合成資料。安全與無障礙不能為趕工省略。

按本輪授權交付最少文件或修改：對應問題與證據、候選／核准狀態、受影響檔案、實際檢查及未驗證事項。產品修改依 AGENTS 更新版本與紀錄；純文件只補現行 CHANGELOG，不升產品版本、不改 Service Worker 快取。未授權不 stage、commit、push、建立 PR 或 tag。

實作檢查限受影響流程，涵蓋：成功／失敗／空狀態與必要確認、鍵盤焦點與無障礙名稱、桌面與窄螢幕、文字可讀性、減少動態、偏好／草稿／搜尋／返回保留，以及既有安全保護。區分原始碼檢查、合成自動驗證、瀏覽器證據與使用者手測；未查到的項目如實列出，不借用歷史數字。

本次規範建立（2026-10-17）只核對專案根目錄、分支、版本、未提交狀態，閱讀兩套 SKILL 與相關操作／產品文件，並檢查文件相容性、相對連結及修改範圍；不重跑全部產品測試，不作設計或功能驗收。保留前輪安裝與其他既有修改。
