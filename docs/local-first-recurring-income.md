# 0.25.0 收入記帳與每月定期收入

**僅供合成資料測試，請勿輸入真實帳目；IndexedDB未加密，Python Web尚未被取代。**

## 操作與金額

記帳區的「記錄收入」預設收合，與原消費表單並列，共同隸屬不可隱藏的記帳區塊。重用原收入表單、revision、操作紀錄及交易，不建立另一套收入模型。收入查看月份與規劃月份分開，切區保留兩邊未儲存草稿；規劃保留實收歷史與每月分配。

收入是實際收到的錢；分配是每月用途規劃，可未分完或超過當月收入；生活預算是支出上限。三者不表示轉帳或實際存款餘額。新增／更改／作廢收入只更新實收，不自動保存、覆寫分配或替目標增加貢獻。只有「生活開銷」是分配預設，既有自訂項目、目標ID連結及本月／往後建議排除仍保留。

定期收入在「規劃 → 收入與每月分配 → 定期收入」設定名稱、預定金額、首次日期與每月收款日。第一版只支援每月；建立時首次日期須符合當月指定日，短月取月底，後續恢復原指定日。首次日期建立後不可更改；可更改名稱、金額及未來收款日，不重新開立規則ID。

記帳的收入區可查看每一期：未到期不能確認／略過；到期後可明確確認已收到、先帶入原收入表單調整實收日期／金額／來源名稱，或略過。略過可恢復當期，不影響下期；尚未確認不算實收。讀取、切月、重新整理、匯出均不入帳。本月尚未到期的項目只供查看，不預測下月實收。歷史很多時先顯示100期，可繼續查看。

更改／停用規則在同一寫入交易凍結已到期但尚未保存的草稿，保留其原預定名稱、金額與日期。更改的新設定只從未到期月份生效；若新收款日本月已過，由下月生效，本月尚未到期的原草稿仍保留並顯示尚未到期，不能提前確認。停用阻止未來新期數，已到期／略過／已記錄期數保留，已到期草稿仍可確認。極端歷史若凍結會超過100000列則整筆拒絕，不能裁切歷史。

每個規則／月份最多連結一筆實收收入。確認在單一原子交易新增收入及原income_actions，並標記該期已記錄；舊revision、重複確認、雙分頁及任何容量／中止失敗整筆回滾。實收日可與預定月份不同，月收入按實收日歸屬。後續更改／作廢收入不回寫規則或草稿；期數仍已記錄，作廢也不重建。

## IndexedDB與完整備份

前兩階段IndexedDB原子升至**v9**，新增`income_rules`與`income_periods`，共24個store含meta；續作再升至v10／25個store，新增發票關聯見[發票契約](local-first-invoice-import.md)。舊結構升級只補空store並驗證原始列／metadata；沒有新資料時仍按原JSON版本輸出，不重寫舊列或新增收入。

有定期收入資料時完整備份為**JSON v8／二十三類**；v1～v7仍可空白還原，加密封裝v1及密碼流程不變。舊Python及舊local-first不支援v8，必須安全拒絕；不要刪欄位或改版本降級。升級後不要用舊程式開啟已升級資料庫，也不要清除原網站資料。

| 資料 | 欄位 |
|---|---|
| `income_rules` | `id,name,cents,first_due_on,due_day,effective_month,active,revision` |
| `income_periods` | `rule_id,month,defaults,status,income_id,revision`；defaults為`name,cents,due_on` |

狀態只保存pending／skipped／recorded，未到期的upcoming是唯讀投影，不保存也不算收入。規則ID及收入ID須唯一，期數以規則ID＋月份唯一；已記錄須連結存在的收入，且同一收入不能被多期引用，未記錄不得有income_id。預定日期須在該期月份、不得早於首次日期；名稱、金額、日期、狀態、revision及所有原有資料仍須嚴格驗證。更改收入後不強制它等於原草稿快照。

金額仍用精確cents字串與BigInt；新輸入沿用正數、最多兩位小數、十億元台幣上限。儲存／匯入整數與revision受signed64上限約束；完整備份64MiB／100000列不變。空白還原前完整驗證，確認後交易內再檢查空白，失敗不留下部分資料。

## 更新與驗證邊界

固定來源及資料庫名稱不變，快取`local-first-offline-0.25.0-v9`仍19個本機必要資源，沒有新依賴、伺服器API或外部傳輸。更新前自行保存草稿與備份、等資源下載完成、關閉同來源全部舊頁再開；不skipWaiting、不強制刷新、不初始化帳本。

本輪只用合成帳本完成原生交易、實體加密檔下載及不同隔離來源的空白還原；不等於獨立瀏覽器設定檔或正式帳本搬移。完整結果及尚未驗證事項見[本機驗證紀錄](local-first-browser-validation.md)。電子發票合成正常路徑已續作；已釐清負行折扣並以明細合計正數淨額，店家規則未實作，見發票契約。
