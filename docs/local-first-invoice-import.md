# 0.25.1 合成電子發票 CSV 匯入與分類建議

> 日餘拆分註記（2026-10-14）：本文保留原專案的歷史版本、日期、驗證結果及限制，不代表日餘本輪重測。現行程式磁碟目錄為 `web/`；HTTP仍為 `/local-first/`。Windows請雙擊根目錄 `start_local_first.local.cmd`，歷史 Python／Node 指令不是目前使用者操作入口。

**僅供合成資料測試，請勿匯入真實發票或正式帳本。IndexedDB未加密，Python Web尚未被取代。**

使用者釐清同票多品項重複號碼、負行是折扣；核對兩個金額欄逐列相同後修正明細計算。只在記憶體內確認指定案例可解析，未把真實內容匯入帳本或輸出。

## 操作與支援範圍

在「設定 → 資料管理 → 電子發票 CSV 匯入」選檔，先預覽、逐張排除或修正日期／總金額／品名／分類／付款方式，再查看確認摘要，最後才記錄消費。取消、切區、預覽及匯出不入帳。預覽每批50張，選取及修正涵蓋完整結果，不把顯示批次當作匯入上限。

第一版依使用者提供的格式案例，只接受UTF-8（可有BOM）、必要欄位「發票日期、發票號碼、發票金額、發票狀態、折讓、消費明細_品名」。日期為YYYYMMDD；品項列重複同張發票基本欄位。只匯入「開立已確認」且折讓「否」；其他狀態／折讓整張排除並顯示筆數，不猜代碼或扣除退款。折讓、退貨、其他來源及編碼留待後續，沒有發票API或上傳。

一張發票只有一筆手動生活消費，有明細時以精確cents加總正負明細金額（已含數量，不再乘單價），不另加一次發票總額；不同品名依原順序合併、重複名稱只列一次。明細模式須每列票額等於明細額，或票額重複為同一整張總額且等於明細合計；缺明細列時只接受同票一致正數總額。日期／狀態／折讓不同或兩欄無法核對則拒絕整檔。零／負淨額整張排除，不取絕對值、不新增退款收入。同張品項須連續完整；完整相同票區塊再次出現只取一次，不同區塊同鍵但內容不同則拒絕。相同明細列可能是實際多次購買或檔案重複，不能擅自刪行；預覽不自動填金額，使用者須核對並手填整張總額。原始票號不可把不同發票替換成同一示例號，亦不用日期＋金額判重。CSV引號、逗號及品名換行以字面解析。尾端單欄非發票列只顯示未匯入筆數，不把尾註當指令或消費；其他缺欄／孤立品項拒絕。

最多4MiB、10000 CSV列、1000張發票；新金額沿用正數、最多兩位小數及十億元上限。品名超過200字須在預覽自行修正，不靜默截斷。新日期不得晚於台灣今天，分類及付款方式必須仍啟用；確認時在交易內重新驗證。消費、月曆、搜尋、預算、分析及CSV沿用原消費資料與實際日期，不另記品項費用。

## 店家與預設分類

沿用既有合成格式契約的選用「賣方名稱」，沒有該欄或留空仍可匯入；不猜別的店名欄、不讀真實發票。店名只去除前後空白（沿用名稱空白處理並移除JS空白），不改大小寫、不作模糊或Unicode名稱合併；同張票的店名須一致，矛盾拒絕。名稱最多200字、禁止控制字元；惡意文字僅作文字顯示。CSV店名只留在當次預覽，消費／發票關聯不新增店名欄；使用者明確保存的規則則在本機及完整備份保留。

在「設定 → 分類管理 → 店家分類規則」新增、更改或確認移除「店家名稱 → 啟用分類」。同名店家只能有一條規則；更改／移除檢查revision，任一寫入失敗完整回滾。分類停用保留規則但不採其建議；分類更名在原分類交易中同步規則引用並遞增其revision。規則不回寫消費，預覽手動分類也不建立新規則。

建議順序：完整店名匹配且目標分類啟用 →「發票」→ 若已手動停用發票，則只用啟用的「其他」→ 兩者停用時留空，要求明確選取。缺少「發票」時預覽提供「確認匯入時建立」選項；僅在已選發票使用它的確認交易內，重新讀取並驗證目前分類後建立。手動覆寫優先；選檔、預覽、排除全部、取消與失敗都不新增分類或規則。不自動重新啟用任何停用分類。

## 去重、原子交易與備份

0.25.0的IndexedDB v10新增不可直接更改的`invoice_imports`關聯：`{key,expense_id}`。key為`e_invoice_YYYY_`加上小寫正規化的兩字母／八數字發票號碼，年份取原發票日期；消費仍使用原本的獨立ID。合法舊備份中的不透明ID不被解讀為發票，沒有回頭自動連結舊消費。

匯入在單一交易內重讀全部帳本、檢查每張key尚未使用及選項有效，才一起新增消費、原操作紀錄、發票關聯與metadata。任一重複、跨分頁競態、容量或寫入失敗，整批回滾並保留預覽；不得逐筆開交易造成半套成功。衝突後需重新載入並預覽。後續更改日期、金額或作廢消費不改原發票key，已作廢也不能重建。

有發票關聯時完整備份為**JSON v9／二十四類**，新增`invoice_imports`；嚴格驗證key、唯一性及一對一手動消費引用，可引用已作廢消費。舊v1～v9仍可空白原子還原，無發票關聯仍按原資料選擇版本。舊Python還原會重編ID，故不擴充Python；舊Python及最高v8的local-first必須安全拒絕v9，不能刪關聯或降版。加密封裝v1、64MiB／100000列及空白還原契約不變。

0.25.1原子升級IndexedDB至**v11／26個store含meta**，只新增`merchant_rules`：`{id,merchant,category,revision}`，v10升級不改原資料、metadata或JSON v9備份位元組。含規則時完整備份為**JSON v10／25類**，嚴格驗證唯一ID／正規店名、非負整數revision及存在的分類引用；允許已停用分類引用以保留規則歷史。無規則仍輸出原適用版本（有發票為v9）。新格式舊讀取器須安全拒絕，不能刪規則或降版；空白帳本還原仍在交易內重新檢查，任何失敗不留下部分資料。加密封裝v1不變。

發票識別屬帳本資料，會保存在本機及完整備份；IndexedDB仍未加密，加密只保護下載檔。除必要識別、消費總額及合併品名等確認欄位，不保存CSV原檔、載具、店家地址／統编或品項單價。使用者文字只以安全DOM文字顯示，不寫入網址、日誌、靜態快取或外部服務。

離線必要資源仍19檔，沒有新增依賴；最終快取及實際測試結果見[本機驗證紀錄](local-first-browser-validation.md)。更新不得強制重新整理或清除原帳本；先自行保留草稿與完整備份，等下載完成、關閉同來源舊頁再開。
